作品说明

《蓝色边界：珊瑚修复站》是一款面向珊瑚礁修复科普的单页互动原型：使用者扮演礁区修复站值守员，在 4 个阶段内支配 8 点行动资源，围绕苗圃移植、浑浊源治理、热压力缓冲与社区巡护宣教四项手段做取舍，并观察指标随之发生的变化。

目标用户

  • 高校与中学的海洋生态类通识课程、社团科普活动（单次使用时长约 5–10 分钟）。
  • 科普场馆、海洋主题展项中作为自助式解说补充。
  • 对珊瑚白化与礁区修复议题感兴趣的一般公众。

不适用场景

任何需要真实数据或专业结论支撑的科研评估、工程设计与管理决策，均不适用于本作品（详见"边界声明"）。

创新点一：规则全透明、结果可复算

作品不使用隐藏数值或随机抽奖：行动的成本、增量、折减阈值与自然上升趋势全部在界面上公开，并随导出文件一并输出。学习者可以逐步复算每一次变化，把"结果好不好"转化为"规则是否被理解"。这与多数科普小游戏把数值演算放在黑箱里的做法形成差异。

创新点二：副作用与延迟响应构成可重复的对照实验

每项行动同时呈现"作用假设"与"副作用/风险"，且存在时序依赖（先改善清澈度，移植才能充分生效；热压力每阶段末自然上升，使收益被时间稀释）。配合逐步撤回与最多 3 条策略快照并排对比，同一初始条件下可多次重演不同策略，从"单次通关"变成"可对照的策略实验"。

创新点三：把不确定性前置到界面与数据里

生态科普常见缺口是把游戏数值包装成科学结论。本作品把知识卡与边界声明放在同一操作层（随时可查），知识卡明确标注"待生态相关专业人员审核"，导出文件同时记录尚未验证的环节，使"已知/未知/待验证"在使用者眼前保持可辨识，并把不确定性本身作为教学内容。

规则模型

确定性状态机：state = {回合, 资源, 活力, 清澈度, 热压力, 多样性, 社区支持度}。结算顺序为"扣除行动点 → 判定折减/递减条件 → 应用增量 → 指标 clamp 至 0–100 → 阶段末热压力自然上升"。全部结果由输入决定，无随机项，可重复复现。

数据流

用户点击 → 规则函数计算并记录 undo 快照 → 更新 state → render() 刷新面板 DOM → draw() 重绘 Canvas → 退出时 exportData() 序列化为 JSON。

模块划分

  • 数据层：常量、初始指标、四项行动的定义（含成本、假设、风险、知识卡文案）。
  • 规则层：行动结算、折减判定、阶段推进、撤回栈。
  • 视图层：指标面板、行动卡折叠区、快照对比列表、复盘区。
  • 输出层：JSON 导出。辅助层：Canvas 绘制、知识卡弹窗、说明抽屉。

四项指标的定义与取值范围

四项指标统一取整数、范围 0–100，全部为本页设定的教学假设量，不对应任何真实监测口径：

指标含义（模型中）初始取值约定
群落活力 health礁区造礁珊瑚整体状态的综合示意量38越高越好；主要由苗圃移植抬升，受热压力上升间接拖累
水体清澈度 clarity水体透明度示意量，代表光可到达的程度42越高越好；阈值 45 是移植能否充分响应的分界
热压力 heat热胁迫强度示意量68越低越好；每阶段末自然上升，是唯一会自行恶化的指标
生态多样性 diversity礁区物种丰富程度的示意量27越高越好；受移植直接抬升，并被社区支持度附加

约束：所有指标在每次结算后 clamp 至 0–100；同一操作序列结果完全一致，不含随机项。

行动效果的设定逻辑（为什么这样取值）

  • 成本与收益成对设计：成本高的行动单项收益大（苗圃移植 3 点换活力 +13 / 多样性 +9），成本低的行动单项收益小（社区宣教 1 点换活力 +1 / 多样性 +1），使"每次决策"都必须回答"值不值"，而不是无脑点满。
  • 总量约束：全程 8 点资源、4 个阶段，四项行动按成本 3/2/3/1 组合后最多执行 5–6 次，无法把四种手段都做到位，取舍因此成为作品的核心体验。
  • 初始值刻意偏低：活力 38、多样性 27 留出上升空间，清澈度 42 恰好低于阈值 45（使"先治水再移植"成为可发现的前置关系），热压力 68 高于阈值 45（使第一阶段的缓冲手段不落入递减区间）。
  • 单项幅度控制在 10–20 点：一次行动可见但不至于一步到位，保证 4 个阶段都有可感知的变化，也避免单次决策直接决定成败。
  • 说明：以上取值为可玩性与教学表达服务的假设，未取自实测数据，也未经过专业人员校准。

边际递减与折减规则的设计意图

  • 清澈度 < 45 时移植折减至约四成：把"浑浊水体限制移植成效"这一常见科普表述，转译成可计算的门槛，让"先后顺序"产生实际后果，而不是口头提醒。
  • 热压力 < 45 时缓冲降温由 -15 递减为 -7：表达"胁迫已经不高时，继续投入的边际收益下降"，引导学习者把有限资源投向更紧迫的方向。
  • 社区支持度上限 3 且重复宣教收益极低：避免单一低成本手段被无限重复堆叠成万能解，同时体现社会过程难以被单一变量线性刻画。
  • 两条阈值规则都公开在界面与导出文件中：设计目的不是"惩罚玩家"，而是让阈值可被发现、可被复算、可被讨论。

热压力自然上升的意义

  • 模型里唯一"不行动也会变差"的指标：每阶段末上升 3 点，用于表达外部驱动因素不完全由值守员的投入决定。
  • 它使收益被时间稀释：即使本阶段成功降温，若不持续投入，后续阶段仍会回升，从而把"一次性修复"与"持续维护"的区别变成可观察的现象。
  • 它与社区支持度耦合：支持度每积累 1 点，阶段末上升量减 1（下限 1 点），使最便宜的宣教行动产生跨阶段的延迟收益，为"短期弱、长期有用"的手段留出存在价值。
  • 该设定同样为教学假设，不代表任何真实升温速率或趋势预测。

运行方式

双击 coral.html 用任意现代浏览器打开即可（本地 file:// 方式同样可用），无需安装环境、无需联网。

最小操作步骤

  • 1. 阅读右侧四项指标与初始情境说明。
  • 2. 点击行动标题展开"作用假设 / 副作用风险"。
  • 3. 需要背景知识时点击该行动的"知识"按钮查看科普卡。
  • 4. 在资源允许范围内选择行动，可连续分配；完成后点"结束本阶段"。
  • 5. 4 个阶段结束后填写复盘三问，点"导出决策记录"得到 JSON 文件。

随时可用"撤回上一步"回退、用"重新开始"重置本轮（快照列表不会被清空，便于跨轮对比）。

场景绘制方式总览

礁区画面由 Canvas 2D 逐帧代码绘制，不使用任何位图、图标、字体或第三方素材；每次指标变化后重新绘制，画面与状态始终一致。画布按 devicePixelRatio 缩放并在窗口尺寸变化时重算，避免高分屏模糊。

图层绘制方式随什么变化

悬浮颗粒46 个由确定性序列定位的半透明圆点（气泡/悬浮物）仅随指针或触摸焦点平移，不随指标变化
礁石地形由正弦函数生成折线并填充海底轮廓固定轮廓，作为珊瑚的承载基底
珊瑚生长递归分支函数绘制，分支深度上限 5 层，末端继续分叉并逐级缩短、变细数量随群落活力增减；分支长度随活力缩放；颜色按状态切换（热压力 > 72 偏灰褐、清澈度 < 40 偏土色、常态偏橙）

视觉与交互上的取舍

  • 画面为示意性表达：追求"指标变化看得见"，不追求写实，也不代表任何真实礁区的外观。
  • 观察焦点交互：鼠标移动或触摸拖动会平移颗粒与鱼群层，提供轻微的临场感；不依赖该交互也能完整使用。
  • 弱动效偏好：页面遵循 prefers-reduced-motion，开启该系统设置时不播放过渡动画。
  • 性能：绘制为一次性静态重绘（非持续动画循环），仅在状态变化、焦点移动与尺寸变化时重绘，低性能设备也能流畅运行。

建议的使用流程（约 20 分钟）

  • 体验 5 分钟：不讲解规则，先让使用者独立完成一轮四阶段决策，遇到疑问可自行展开行动卡或知识卡。
  • 比较 3 条策略：重新开始后换一条思路，把每条结果存为快照（最多 3 条），并排比较终值与剩余资源，讨论"哪条更好、按什么标准算好"。
  • 复盘讨论 10 分钟：围绕下方三个问题交流，并把回答写入复盘区导出留存。

配套的三个讨论问题

  • 清澈度低于阈值时移植会折减：这个设定对应现实中的什么限制？它是否改变了你的分配顺序？
  • 热压力每阶段末自然上升：模型为什么要引入"不行动也会变差"的机制？它如何影响你的长期安排？
  • 本页哪一处变化明显来自规则设定而不是真实生态规律？如果要改进，你会先改哪一条、依据是什么？

带领者需要注意的边界（请在使用前说明）

  • 不要把指标当真实预测：四项数值、阈值与响应关系均为本页设定的教学假设，不来自真实海域监测数据，不能用于判断任何真实礁区状况，也不能作为修复决策、生态预测或环境评估的依据。
  • 不要把"通关结果"当标准答案：模型没有唯一最优解，作品的目标是让取舍依据被说出来，而不是收敛到某个分数。
  • 知识卡仍待专业审核：卡片为科普性初稿，页面上已标注"待生态相关专业人员审核"，讲解时请一并说明这一状态，不要当作专业结论转述。
  • 尚未开展用户测试：目前没有目标用户的完成率与主观反馈数据，使用时请留意参与者的实际理解情况，必要时由带领者补充讲解。
